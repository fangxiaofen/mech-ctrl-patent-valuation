# 机械装置 + 控制方法组合型专利价值评估方法论

本文件是该 Skill 的核心知识库，提供组合型专利（同时含**机械结构装置权利要求**与**软件/算法/流程控制方法权利要求**）价值评估的完整维度、检查清单与全球评估体系溯源。SKILL.md 仅做流程编排，详细研判规则在此。

---

## 0. 组合型专利的专属特征（评估前必读）

此类专利的典型结构：
- **独立权利要求 1**：机械装置（构件、连接关系、装配关系、运动副）。
- **另一独立权利要求**：控制方法（步骤时序、触发条件、输入输出、执行主体=硬件控制器）。
- **对应从属权利要求**：机械结构参数、控制算法参数、工况条件分层限定。

四大组合场景（强制判定其一，用于后续所有模块）：
1. **装置为核心，控制方法只是配套优化** —— 价值锚定机械，控制权重低。
2. **控制方法为核心，机械装置是通用载体** —— 价值锚定控制算法，但取证风险高。
3. **装置 + 控制耦合，二者必须一起使用** —— 协同创新，拆分许可难，规避难。
4. **装置、方法可拆分，可单独许可实施** —— 许可灵活，但需分别评估侵权与规避。

通用专利评估体系对此类专利的短板（修正动因）：
- 不区分“实体机械权利”与“方法权利”的差异化风险；
- 忽略方法专利侵权取证难度（运行在控制器内部，外部不可观测）；
- 不评估硬件成熟度与控制算法成熟度不一致（TRL 分离）；
- 缺少装置-方法对应缺陷（方法步骤无对应硬件构件）的扣分。

## 0.5 通过专利号检索基础元数据（仅给号时必做）

当用户**只提供专利号 / 申请号**（如 `CN201811222243`、`US20210339406`、`WO2020/xxxxxx`），未提供全文时，先按本模块回填元数据，再进入后续评估；若同时提供全文，以全文提取为准、检索仅补全交叉验证。

### 0.5.1 检索动作（世界流行公开源）
- 用 `WebSearch` 检索 `"<专利号> 申请人 法律状态 同族 权利要求"`，定位专利库页面；
- 用 `WebFetch` 抓取以下任一/多个来源提取字段：
  - **Google Patents** `https://patents.google.com/patent/<公开号>/`（同族、法律状态、引用、权项）
  - **PatSnap / 智慧芽 / incopat**（权项结构、家族、诉讼）
  - **CNIPA 专利公布公告 / 专利审查信息查询**（中国法律状态、年费）
  - **企查查 / 天眼查 专利页**（申请人、法律状态）
- 若 netdrive/本地已提供 PDF，优先从 PDF 提取，检索仅作补全。

### 0.5.2 需回填的字段
| 字段 | 含义 | 算法/来源 |
| --- | --- | --- |
| applicant | 申请人 | 检索页 "Assignee/Owner" |
| legal_status | 法律状态 | 申请 / 实审 / 授权 / 驳回 / 无效 / 届满 |
| filing_date | 申请日 | 检索页 "Application Date" |
| remaining_term | 剩余期限 | `申请日 + 20年`（发明/utility，按法域）− 当前；`generate_report.py` 可据 `filing_date` 自动计算 |
| family_count | 同族数量 | 同族/家族成员计数（含 CN 发明 + 实用新型 + 海外同族） |
| jurisdictions | 布局地域 | CN / US / EP / JP / KR … |
| innovation_type | 创新类型 | 依据独立权项是否含控制方法判定：`机械主导 / 控制主导 / 耦合协同 / 纯机械装置 / 纯控制方法` |

### 0.5.3 校验与兜底
- 检索不到精确值（尤其同族数量、法律状态）时填"建议核验"，并在风险清单标记，**禁止编造**；
- 在 JSON `patent.metadata_source` 标注来源，报告中注明"元数据来源：公开专利库检索（建议 CNIPA 核验）"。

## 一、法律维度价值（通用框架第一层）

### 1.1 权利基础状态
- **地域布局**：授权国家/地区数量；是否含中国、美、欧、制造业重点国；PCT 进入状态；同族专利数量及各自授权/驳回状态；同族是否存在权利要求缩限。
- **法律状态**：授权 / 实审 / 驳回 / 无效；是否经历无效、异议、复审；是否存在权属纠纷、质押、许可备案、转让记录。
- **剩余保护期限**：各法域剩余年限；机械装置专利因产品迭代快，剩余年限权重高于纯软件专利。

### 1.2 权利要求质量（核心差异点）
- **独立权利要求完整性**
  - 装置独权：是否完整全部必要技术特征；是否清楚限定机械构件、连接关系、装配关系；是否避免功能性限定泛滥。
  - 方法独权：控制步骤时序、触发条件、输入输出、执行主体（硬件控制器执行）是否完整；方法步骤是否与装置结构特征互相呼应。
- **保护范围清晰度**：是否存在模糊术语；装置与方法之间是否存在**对应关系缺陷**（方法步骤在装置中无对应硬件构件，或装置结构无法实现该控制逻辑）。
- **从属权利要求价值**：是否对机械结构参数、控制算法参数、工况条件做分层限定；是否构建多层防御抵御无效宣告。
- **撰写缺陷风险**：公开不充分；机械结构附图是否支持权利要求；控制方法逻辑是否在说明书充分披露（避免“算法黑箱公开不足”）。

### 1.3 侵权可检测性（关键，易忽略）
- **装置**：终端产品是否易拆解取证；机械结构外部可见还是封装内部不可观测。
- **控制方法**：控制逻辑运行于控制器内部，外部不可直接观测；是否存在可观测的输入输出行为/外部特征便于取证；是否需反向工程判定侵权。
- **全球实践**：纯方法专利侵权取证难度显著高于实体装置，直接下调专利价值。

## 二、技术维度价值（融合 WIPO / IPscore / PatSnap 指标）

> **打分方式（核心）**：技术维度不做单一整体打分，而是**强制三段拆分、各打 0–5 子分、再加权合成**——
> `技术价值 = wm·SM + wc·SC + wk·SK`（wm+wc+wk=1，权重来自 §六 Cf3 的创新贡献拆分）。
> 其中 `SM`=机械装置创新子分、`SC`=控制方法创新子分、`SK`=软硬件耦合协同创新子分。
> 这是"机械/控制/耦合三评价通过各类价值加权打分"的落地公式；其余维度（法律/市场/权项质量/落地）按 §七 的世界流行方法打分。

### 2.1 创新高度
- **创造性高度**：区分**机械部分创新贡献** vs **控制方法部分创新贡献** vs **软硬件协同贡献**
  - 机械（SM）：结构改进、构型、装配、材料、运动副改进；
  - 控制（SC）：算法逻辑、调度策略、闭环控制、故障处理、工况自适应逻辑；
  - 耦合（SK）：机械-控制协同带来的超额效果（如"小惯量硬件 + 高带宽控制"协同增益、结构-算法联合降耗）。
  - 强制判定创新类型：机械主导 / 控制主导 / 二者协同 / 纯机械 / 纯控制。
- **新颖性**：是否存在多份抵触申请、现有技术覆盖；装置与方法两个独立主题是否分别被现有技术冲击。
- **技术效果明确性**：说明书是否定量记载；是单纯结构效果，还是"机械硬件 + 控制策略协同耦合效果"。

### 2.2 技术成熟度 TRL（Ocean Tomo 重点）
- TRL 1-3：概念方案，仅仿真无样机；
- TRL 4-5：实验室样机，台架试验；
- TRL 6-7：原型机现场验证；
- TRL 8-9：量产落地产品。
- **特殊风险**：机械硬件已样机成熟但算法仅仿真；或算法仿真好但机械加工精度无法满足算法工况。二者成熟度**分开打分**（mechanical_TRL、control_TRL）。

### 2.3 技术替代性与依赖度
- **替代技术**：是否存在其他机械构型 + 其他控制策略实现相同功能；替代成本高低。
- **技术依赖**：是否依赖外部专有硬件、特殊传感器、第三方算法库；是否存在外部技术壁垒。
- **技术迭代寿命**：机械硬件迭代周期长、绕开难；控制软件算法迭代周期短、易被后续算法绕开。

### 2.4 公开充分度
- 机械部分：附图、尺寸关系、装配关系、加工工艺是否充分；
- 控制方法部分：控制逻辑、参数范围、案例、边界工况是否充分（避免仅给任务目标缺实现路径）。

### 2.5 引用指标（专利计量）
- 后向引用：被后续专利引用数量，区分引用机械结构 / 控制方法；
- 前向引用：本专利引用的现有技术数量；
- 同族引用差异；自我引用占比。

## 三、市场与商业价值维度（LRF / Ocean Tomo 估值）

### 3.1 目标应用市场规模
- 专利对应产品整机市场容量，区分机械硬件市场 vs 配套控制软件市场；
- 目标市场渗透率、市场增速、地域市场差异。

### 3.2 专利在产品中的地位（核心指标）
- **基础核心专利**：整机必须同时采用该机械结构 + 该控制方法，无法绕开；
- **优选改进专利**：产品优化方案，可替换其他方案；
- **周边配套专利**：仅局部附属功能。
- 与“四大组合场景”联动研判。

### 3.3 许可、转让、商业化潜力
- **许可场景**：是否可拆分许可（单许可机械 / 单许可控制 / 整体打包）；
- **潜在实施主体**：行业头部企业数、中小厂商数；
- **壁垒**：是否可作交叉谈判筹码；是否适合诉讼、无效对抗。

### 3.4 成本收益约束
- 实施成本：机械开模/加工、控制器硬件、算法开发调试、改造成本；
- 增量收益：降本、增效、良率提升、能耗降低等对比现有方案。

## 四、风险维度（高权重项）

1. **实施耦合风险**：机械结构制造公差直接影响控制算法能否达到宣称效果；图纸理论可行，量产性能不达标。
2. **绕开风险**
   - 机械装置：结构变形、等效替换规避；
   - 控制方法：调整算法流程、参数阈值、逻辑顺序规避（纯控制方法更易被规避）。
3. **产业化风险**：零部件供应链成熟度；控制算法调试难度与周期成本。
4. **标准关联风险**：专利是否落入行业标准；标准必要专利（SEP）风险。

## 五、跨专利对标模块

当用户提供多篇（或同族/竞品）专利时，进入对标分析：
- 同维度横向打分对比（雷达图叠加）；
- 创新贡献拆分对比（机械 vs 控制占比）；
- 成熟度对比（mechanical_TRL vs control_TRL）；
- 风险点对比；
- 综合价值分级排序。
对标结果用于识别“组合中最具许可/诉讼价值的一篇”或“需补强的一篇”。

## 六、专属修正因子（融合评估时必加）

| 因子 | 符号 | 取值与规则 |
| --- | --- | --- |
| 控制方法侵权取证难度系数 | Cf1 | [0.6, 1.0]：外部可观测/可测 → 1.0；需反向工程 → 0.6~0.8。乘入法律价值分。 |
| 软硬件成熟度不一致扣分 | Cf2 | 若 \|mechanical_TRL − control_TRL\| ≥ 2，扣分 [−10, 0]，差值越大扣分越多。 |
| 创新贡献拆分系数 | Cf3 | `wm`（机械贡献占比）+ `wc`（控制贡献占比）+ `wk`（耦合贡献占比）=1；纯机械：wm=1、wc=wk=0；纯耦合：wm=wc=0.4、wk=0.2。该权重用于加权技术三维子分与许可/规避分析。 |
| 权利要求装置-方法对应缺陷扣分 | Cf4 | 存在对应缺陷 → 扣分 [−10, 0]。 |

## 七、融合的全球评估体系溯源

| 评估体系 | 来源 | 核心维度 | 针对机械+控制专利的短板 |
| --- | --- | --- | --- |
| WIPO 专利价值评估工具 | WIPO | 法律、技术、市场 | 对“装置-方法耦合创新”、方法取证难度无专门指标 |
| IPscore | 欧洲 | 法律状态、权利要求、技术、市场、TRL | 缺硬件-软件成熟度分离评估 |
| Ocean Tomo 估值模型 | 美国 | 专利计量、市场、许可历史、诉讼数据 | 偏重已商业化专利，对实验室样机弱 |
| Relecura 专利评估 | 国际 IP 平台 | 引用指标、同族、权利要求、市场 | 不区分机械实体权利与方法权利风险 |
| 国知局专利价值分析指标体系 | 中国国知局 | 法律、技术、经济 | 缺控制方法取证难、软硬件耦合风险专项 |
| LRF（Law-Risk-Finance） | IP 金融通用 | 法律、风险、财务收益 | 需人工补充技术内部软硬件拆分研判 |

**处理逻辑**：不直接套用单一体系，做融合评估，并叠加上述四个专属修正因子。报告“对标全球评估方法说明”段落须声明融合了哪些体系、做了哪些针对修正。
